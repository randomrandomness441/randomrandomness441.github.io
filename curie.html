Curie

Two tools in one local app. One teaches concurrency by compiling your code and actually trying to break it. The other reads job postings the way a person would and writes a resume that can't claim more than you've actually done. Named for Marie Curie: genuinely multidisciplinary, not a narrow single-purpose tool.

role: solo build stack: Python, C++, Java, vanilla JS context: self-initiated, built to actually prep with timeline: ongoing

Background

core question:
What does a tool that actually teaches concurrency, not just quizzes it, need to check?

Most interview prep asks you to explain concurrency in words. Explaining it and writing code that doesn't race under load are different skills, and the gap between them is exactly where real bugs live. The other half came from the same frustration pointed at job hunting: generic resumes get generic rejections, and writing a new one by hand for every posting doesn't scale, but letting an LLM invent accomplishments you never had is worse than not applying.

goal
"It actually reads the posting against your real work history, the way a person would, and tells you why."
— from the project README

Design

decisions and their defense

One process serves both halves from a single stdlib HTTP server, no framework. The two apps don't share a database or a UI, only a port and a house style.

A verdict, not a pass/failcompile, then ThreadSanitizer, then 150 stress runs under randomized scheduling delay — each stage only runs if the one before it came back clean, and "passes but races" is its own verdict, not a pass
A fallback chain with memoryz.ai first, then a real Anthropic key if set, then the Claude CLI itself on a subscription's own usage window; if z.ai fails, it's skipped for 300 seconds instead of re-paying retry cost on every call
Data and code physically separatedafter a personal seed script with a real name and phone number leaked into the first snapshot commit, every database and generated file now lives under one data/ folder, and a single sync script is the only thing that publishes

Logic

the rules of the system

Before a resume renders, a hard style gate checks the drafted summary and cover letter: no em dashes, no AI-slop phrases, none of the hedge-then-reveal sentence shape it bans by name. It's a stop, not a warning. Near-duplicate point-bank bullets get clustered before selection (character-sequence similarity, threshold 0.82) so a bullet edited into a slightly different phrasing, with the old version accidentally left active, can't land on the same resume twice and double-count toward keyword coverage. The one-page trim loop renders, checks the real PDF page count, drops the single lowest-value bullet if it overflowed, and repeats until it fits or runs out of bullets to drop, so it always terminates. The LLM's fit judgment and the literal ATS keyword estimate are reported as two separate numbers on purpose: one reasons semantically, the other counts text matches, and a posting can score high on one and low on the other without either number being wrong.

Improvements

to resolve: honesty reads as competence
  • STYLE: the AI-slop rule set is hand-maintained; a determined model can probably still find a phrasing it allows that still reads synthetic
  • SETUP: needs Python, LibreOffice, and an API key before it does anything useful, not a one-click install
  • COVERAGE: the concurrency packs span eight topics so far; most real interview topics aren't packs yet
  • UX: the judge score and the ATS estimate can diverge on the same posting, and the UI doesn't explain in-line why that's expected
