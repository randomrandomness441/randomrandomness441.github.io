Kapitsa

A pipeline that reads quiz decks and recorded quiz videos, tells a reasoning question from a recall question, and finds the real article each one was built from.

role: solo build stack: Python, Qdrant, Ollama, Groq / Cerebras / z.ai context: self-initiated timeline: ongoing

Background

core question:
Can you tell a reasoning question from a recall question automatically, and can you trust your own answer?

The Indian quiz circuit calls a well-built puzzle question a "funda": you're given odd clues, and when the answer lands, they click into place. Most of what's actually quizzed is the other kind, a plain memory test. Telling the two apart by hand doesn't scale past a few hundred questions. Telling them apart with an LLM turned out to hide a trap: the easiest way for a judge to look accurate is to just measure how long the question is, since real fundas run much longer than real trivia. A judge that's secretly a length detector will still score well on held-out data, because the held-out data has the same length bias baked in.

from the build log
"A rule with no model in it, 'call a question constructed if it's at least 140 characters long,' matched the labels 91.5% of the time. My LLM judge matched them 92.3% of the time."
— post 01, the baseline that almost wasn't run

That 0.8-point gap is the reason this project keeps a build log instead of just a changelog. Seven posts so far, each one a specific way a measurement looked right and wasn't: a judge that was secretly reading length, a feature that threw away the one signal that mattered, a video crop that silently clipped slide text for months.

Design

decisions and their defense

The rule running underneath all of it: an AI's opinion doesn't count as proof. Every verdict has to come with something checkable, and every score gets compared against a dumb baseline before it's trusted.

Extract → Judge → Source → Generatedecks and quiz videos in, a question bank out, a trained generator the eventual goal
No derivation, no verdictthe judge has to write out how the clues reach the answer, or the code throws the call away
Seven types, found not designedclustering specific descriptions gave 107 useless one-question clusters; clustering coarse families gave seven that actually hold examples

Logic

the rules of the system

The judge distinguishes EXPLAINS from SATISFIES: does the answer account for the clues in the question, or does it just fit them without the setup needing it to be that specific answer? "Known for his red helmet, who won the 2018 Monaco Grand Prix" is SATISFIES, Ricciardo fits but the clue doesn't require him. Swap the clue for something the answer actually explains and the same facts become EXPLAINS. The difficulty signal works the same honest way: a small model guesses with no internet and no notes, and if it can't get there, the question is harder, not because anyone labeled it that way.

Source-finding has a real ceiling, not a bug waiting on a fix: about one in five questions in the bank use knowledge no article search turns up. That number gets reported as-is rather than chased to zero, because the honest version of this project is more useful than a prettier one.

Improvements

to resolve: honesty reads as competence

  • COVERAGE: about 1 in 5 funda/answer pairs cite knowledge with no findable source article
  • RELABEL: the full question bank hasn't been re-run against the current judge yet
  • DIFFICULTY: only coarse easy / medium / hard buckets so far, no finer scale
